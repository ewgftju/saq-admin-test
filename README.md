# SAQ — Администрирование

Интерактивный тестовый стенд единого управления ролями SAQ.

## Что работает

- Каталог 60 назначаемых профилей в 10 разделах, фильтры и выгрузка CSV.
- Пользователи, организации, блокировка и журнал изменений до/после.
- Модульные назначения с областью, сроком и основанием; отзыв доступа.
- Редактирование подмножества разрешений базового профиля и создание его копий. Ограничения профиля сохраняются.
- Замещение внутри одного органа, только в пределах собственного исходного назначения.
- Редактирование шаблонов маршрутов: последовательное/параллельное согласование, утверждение и итоговая подпись отдельно.
- Проверка доступа по назначению, периоду, организации/региону/делу/БИН, адресату, редакции и этапу; отдельная проверка ДСП.
- Защита от удаления последнего системного администратора и самоблокировки; конфликты сохранения между вкладками.

## Каталог

| Раздел | Профилей |
| --- | ---: |
| Администрирование | 3 |
| Профилактический контроль | 12 |
| ВГА | 9 |
| СВА | 8 |
| СУР | 4 |
| Возражения и апелляции | 8 |
| Отчетность | 4 |
| Кадры и обучение | 5 |
| Организационная деятельность | 4 |
| Кабинет ОГ | 3 |

Источник каталога: `public/catalog.json`. Для каждого профиля сохранены происхождение, описание, допустимые действия и области. Коды ролей и формализация отдельных разрешений предложены для новой админки. Состав СВА — предложение по аналогии с двумя предоставленными постановками ВГА. Роли из запроса не означают согласование предлагаемой детальной матрицы.

Исходные четыре профиля формирования полугодового списка сопоставлены с СУР и отдельными назначениями ПК. «Кабинет объекта SAQ» является интерфейсом, а не ролью. Исходные `appeal-head` / `appeal-expert` ВГА сопоставляются с ролями модуля возражений по должностным основаниям; автоматической выдачи дублирующих ролей нет. Администратор не получает право бизнес-утверждения; руководитель КК отделен от утверждающего документов аудита. В ПК нет придуманного профиля утверждающего.

## Граница реализации

Это frontend со стартовыми учебными записями и локальным хранилищем браузера. Адреса `example.test`, БИН и сотрудники фиктивные. Нет аутентификации, серверной базы, отправки уведомлений, интеграции с SAQ, ЭЦП и серверного enforcement. Расчет в «Проверке доступа» демонстрирует модель, но не защищает реальные системы. Не вводите реальные персональные или служебные данные в публичный стенд.

В целевой системе каждый модуль должен проверять права на сервере для чтения, скачивания, выгрузки и записи. Нужны общая идентификация, надежные назначения по ID, немедленная инвалидизация сессий при отзыве, неизменяемый серверный журнал и транзакционные проверки конкурентных изменений. Эти требования изложены в отдельной постановке Word.

Областное администрирование показано в каталоге, но сам стенд работает от учебного системного администратора. Исполнение маршрутов реальных документов, полный жизненный цикл заседаний/обучения, импорт/синхронизация организаций и реальная доставка поручений не входят в этот отдельный UI. Шаблоны маршрутов не заменяют предметные правила и подписи рабочей группы и объекта. Порядок подтверждения реестра ВГА различается по виду аудита и задается предметным процессом.

При блокировке пользователя его назначения сохраняются, но не работают; последующая активация возвращает только еще действующие назначения. Замещение не переносит допуск ДСП и не дает чужую ЭЦП. Даты включают последний день и проверяются в `Asia/Qyzylorda`.

## Запуск и проверка

Требуется Node.js 22 или новее. Внешних npm-зависимостей нет.

```sh
npm test
npm run build
```

Vercel публикует каталог `dist/`. `public/` содержит исходники браузерного приложения, `domain.mjs` — расчет прав и валидации, `seed.mjs` — учебные данные. Никакие исходные пользовательские Word/Excel файлы в публичный репозиторий не включены.
